基本構造

標準構造は、共通テンプレと本番repoを分離する設計です。共通テンプレはコピー元として残し、実際にRailwayで動くのはキャラクターごとの専用repoです。これにより、どのBOTを直しているのか、どのRailway serviceへ反映されるのかが明確になります。

処理の流れ

Plugin本体は、mixi2から投稿や参加イベントを受け取り、handlerで種別と条件を判定します。返信やお題生成が必要な場合はOpenAIへ生成を依頼し、結果をmixi2 APIで投稿または返信します。定時投稿や静寂投稿はscheduler側が担当します。

標準フォルダ

場所役割注意
base-bot共通テンプレ。新しいPluginを作るコピー元。本番Railwayには使わない。
mixi2-community-voidcat-plugin虚無猫本番repo。personas/kyomu_neko と assets/kyomu_neko を持つ。
mixi2-community-fujita-pluginシベリア・フジタ本番repo。personas/fujita と assets/fujita を持つ。
mixi2-community-nan_ai-plugin空想アイ本番repo。personas/nanchatte_ai と assets/nanchatte_ai を持つ。
voidcat-plugin-notes公開ノートrepo。Plugin本体ではない。秘密値なし。

本番repoを1人格に絞る理由

base-botのような共通テンプレでは複数人格を持っていても問題ありません。むしろ、テンプレートとしては複数の例がある方が便利です。しかし、本番で動く専用repoに複数人格や複数キャラ素材が残っていると、更新時に判断が鈍ります。Voidcatを更新したいのにFujitaのpersonaが見えている、Nan AI用のassetsが残っている、という状態は不要な混乱を生みます。

専用repoは「このrepoは誰のBOTか」が一目で分かることを優先します。コード本体は共通でも、personaとassetsは1つに絞る。これにより、Railway VariablesのPERSONA、PERSONA_PATH、IMAGE_REF_DIRも単純になります。

構造確認コマンド

cd C:\dev\mixi2-plugins\mixi2-community-voidcat-plugin
Test-Path .\personas\kyomu_neko\persona.json
Test-Path .\assets\kyomu_neko\refs
go test ./...
go build ./cmd/plugin

構造確認では、存在してほしいものだけでなく、存在しない方がよいものも見ます。たとえばVoidcat専用repoに personas/fujita や assets/nanchatte_ai が残っているなら、運用上は削除候補です。
