基本構造解説

フォルダ構成、機能構成、処理フロー、人格と素材の分離

最終更新: 2026-06-16 mixi2 Plugin GitHub Pages

全体の考え方

現在の構成は、共通テンプレと3体の専用Pluginを分ける方針になっている。共通テンプレはコピー元として使い、実際にRailwayで動かすのは各キャラクター専用repoにする。

標準フォルダ構成

C:\dev\mixi2-plugins
├─ base-bot
│  └─ 共通テンプレ。gitなし。Railway本番には使わない。
├─ mixi2-community-voidcat-plugin
│  ├─ personas\kyomu_neko
│  └─ assets\kyomu_neko
├─ mixi2-community-fujita-plugin
│  ├─ personas\fujita
│  └─ assets\fujita
└─ mixi2-community-nan_ai-plugin
   ├─ personas\nanchatte_ai
   └─ assets\nanchatte_ai

Plugin repo内の構成

場所役割
cmd/pluginRailway本番で動かすPlugin本体の入口。
cmd/configuiローカル専用のブラウザ設定UI。Railway本番では起動しない。
cmd/*checkOpenAI、mixi2、投稿、タイムラインなどの確認コマンド。
internal/config.envやRailway Variablesから設定を読み込む。
internal/handler投稿、返信、歓迎、管理者コマンドなどのイベント処理。
internal/scheduler定時投稿、画像投稿、放置時投稿などのスケジューラ処理。
internal/openaiOpenAI API連携。
internal/mixi2mixi2 API連携。
personas人格設定。専用repoでは原則1人格のみ。
assets画像参照素材。専用repoでは原則1人格のみ。

処理の流れ

  1. mixi2からコミュニティ投稿やイベントを受け取る。
  2. handlerが投稿内容、投稿者、返信済み状態、機能ON/OFFを判定する。
  3. 必要に応じてOpenAIで返信文やお題文を生成する。
  4. mixi2 APIで投稿・返信する。
  5. 処理済みIDや履歴は /data Volumeへ保存する。

人格と素材の分離

人格は personas/{persona}/persona.json、画像素材は assets/{persona}/refs に分ける。これにより、コード本体を変更せずにキャラクターだけを差し替えられる。

PERSONA="kyomu_neko"
PERSONA_PATH="personas/kyomu_neko/persona.json"
IMAGE_REF_DIR="assets/kyomu_neko/refs"
