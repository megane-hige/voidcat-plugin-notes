mixi2公式配布からオリジナルbot化まで

テンプレートを自分のPlugin、自分の人格、自分のRailway環境へ置き換える手順

最終更新: 2026-06-16 mixi2 Plugin GitHub Pages

全体の流れ

公式配布や空のBaseテンプレートを受け取っただけでは、そのまま自分のBOTとして本番運用できるわけではない。自分のmixi2 Pluginアプリ、自分のOpenAI APIキー、自分のRailway環境、自分の人格データ、自分の画像素材を用意して差し替える。

テンプレートをローカルに置く

まず配布されたBaseテンプレートをローカルに置き、go test ./... や go build ./cmd/plugin が通ることを確認する。

自分のGitHub repoを作る

Plugin本体用のPrivate repoを作る。.env、logs、APIキー、Client Secret、実コミュニティのデータは入れない。

自分のmixi2 Pluginアプリを作る

Developer PlatformでPluginアプリを作り、必要なRequirementを設定する。設定後はApplication Version更新とコミュニティへのインストールまたは再許可を行う。

人格を作る

personas/{persona}/persona.json を作り、自分のBOTの口調、禁止事項、反応ワード、投稿方針を設定する。

画像素材を差し替える

画像機能を使う場合は、assets/{persona}/refs に自分の素材を入れる。第三者の権利物や実人物画像の扱いには注意する。

ローカルで確認する

configcheck、gptcheck、mixi2check、timelinecheck、postcheck を使って、段階ごとに確認する。

Railwayへデプロイする

RailwayにGitHub repoを接続し、Variablesへ必要な値を設定する。Secretは空欄で上書きしない。Volumeは /data にマウントする。

本番ログを確認する

Deploy successfulだけで終わらず、missing env、認証エラー、PermissionDenied、panic、投稿失敗が出ていないか確認する。

オリジナルbot化で差し替える場所

差し替えるもの場所説明
人格名PERSONA自分の人格キーへ変更。
人格シートpersonas/{persona}/persona.json口調、ルール、反応ワードを設定。
画像素材assets/{persona}/refs画像機能で使う素材。
mixi2情報Railway VariablesClient ID、Secret、Community IDなど。
OpenAI情報Railway VariablesAPIキー、モデル、画像設定など。
投稿時刻SCHEDULED_POST_TIMESコミュニティに合わせて調整。
機能FEATURES必要な機能だけONにする。

やってはいけないこと

  • 提供者のAPIキーやClient Secretを使う。
  • 提供者のRailway Variablesを流用する。
  • .env をGitHubに上げる。
  • 実コミュニティのログや投稿本文を公開記事に載せる。
  • Requirement変更後にApplication Version更新と再許可を忘れる。
  • 空欄のSecretテンプレでRailwayの実値を上書きする。

完成判定

以下が通れば、オリジナルBOTとして最低限の運用準備ができている。

go test ./...
go build ./cmd/plugin
go run ./cmd/configcheck
go run ./cmd/gptcheck
go run ./cmd/mixi2check
go run ./cmd/timelinecheck
go run ./cmd/postcheck
