第07回：虚無猫の人格調整とconfiguiの追加

persona.jsonを直接編集し続けると、JSON構造崩れ、文字化け、保存ミスが起きやすくなります。そこでConfig UIを作り、ローカルブラウザから人格シートを編集できるようにしました。

Config UIには、人格選択、人格シート、機能ON/OFF、ローカル.env補助設定、Railway Variables確認欄を持たせました。ここで重要なのは、Railway本番を直接書き換えるUIではないということです。

さらに、open-configui.batとデスクトップショートカットを作り、Voidcat、Fujita、Nan AI、base templateを番号選択で起動できるようにしました。

最初は日本語入りbatが文字化けしました。最終版ではASCIIに寄せ、PowerShellのStart-Processでブラウザ自動起動を安定化しました。

Config UIでできることとできないこと

Config UIは、ローカルのpersona.jsonと補助設定を扱うための画面です。Railway本番のSecretを直接変更するものではありません。そのため、画面上ではRailway Variables確認欄を置いても、Secret実値は表示しない方針です。

保存ボタンは、ローカル設定保存と人格シート保存が中心です。GitHub pushやRailway反映を伴う動作は、何が対象になるかを明確にして使う必要があります。

実作業の分解

Config UIは、persona.jsonを安全に触るための補助です。UIで編集できるからといって、本番RailwayのSecretまで自動で変わるわけではありません。ローカル編集と本番Variablesは別物として扱います。

一発起動batは、作業導線を短くするための道具です。文字化けを避けるため、bat内の日本語は避け、ASCII中心にしました。対象repoを番号で選び、Config UIを起動し、ブラウザを開く流れにしています。

この段階で大事なのは、作業結果を「動いた」「動かない」だけで判断しないことです。どの入力に対して、どの設定を読み、どの外部サービスへ接続し、どのログへ残るのかを確認します。BOTは一度動くと自動で投稿・返信するため、目に見える成功よりも、誤作動しないための確認が重要です。

また、ローカルで成功した作業とRailwayで成功した作業は分けて扱います。ローカルでは.envを読みますが、本番ではRailway Variablesを読みます。ローカルではファイルが残っていても、本番ではVolumeがなければ再デプロイで状態が消える可能性があります。この差を毎回意識します。

作業後は、Gitの差分、ビルド結果、確認コマンド、必要ならブラウザ表示を確認します。特に公開ノート側では、HTMLのリンク切れ、スマホでの横はみ出し、モック画像の表示、詳細記事の前後ナビを確認します。
