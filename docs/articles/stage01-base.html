第01〜08段階 / 土台づくり

まずは「動いているPlugin」を壊さずコピーする

今回の作業は、ゼロからBOTを書くところから始めていない。すでに動いているシベリア・フジタPluginがあり、それをベースにして「他の人格にも使い回せるbase-bot」を作るところから始めた。

これは地味だけど大事だった。最初から設計だけ綺麗にしようとすると、どこがmixi2連携で、どこが人格で、どこが投稿制御なのか分からなくなる。なので最初は、動くものを丸ごとコピーして、そこから少しずつ分解する方針にした。

作業フォルダ

作業本体はここ。

C:\dev\mixi2-plugins\base-bot

元になったPluginは別フォルダにあり、そこからbase-botへコピーした。ここで大事なのは、元のPluginを直接いじらず、実験用の作業場を切ったこと。

最初に見たフォルダ構成

base-bot/
  cmd/
  internal/
  personas/
  assets/
  scripts/
  docs/
  Dockerfile
  go.mod
  railway.toml

cmd は起動コマンド置き場。internal はPlugin本体の処理。personas は人格設定。assets は画像参照などの素材置き場。scripts はPowerShell補助、docs は作業メモや仕様書を入れる場所として使うことにした。

GPTとの対話で決めたこと

最初の方針はかなり単純だった。「人格だけ入れ替えたい」「機能をON/OFFしたい」「別コミュニティに持っていけるようにしたい」。この3つをGPTに投げて、既存構造を壊さない範囲で設定項目を増やしていった。

この段階では、まだ綺麗な管理画面もない。PowerShellで確認しながら、Goのビルドが通るか、personaを切り替えられるかを一つずつ見ていった。

この段階で見えたBOT制作の概要

mixi2 PluginのBOT制作は、ざっくり言うと「イベントを受ける」「投稿内容を見る」「必要ならAIで文章を作る」「mixi2へ返す」という流れになっている。人格ファイルは、そのAIに渡すキャラクター説明の役割を持つ。

最初の学び：BOT本体と人格を分けると、同じPluginの仕組みを別キャラに転用できる。
