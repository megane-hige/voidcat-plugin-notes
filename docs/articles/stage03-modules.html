第15〜21段階 / 機能入口の分離

機能を入口ごとに分ける

ここからはBOTの中身を整理した。もともとはhandlerやschedulerの中に、返信、歓迎、お題、定時投稿、画像返信などがまとまっていた。動くけれど、何をON/OFFしているのか分かりにくい。

そこで、各機能の入口を分離した。

handler側

internal/handler/
  admin_entry.go
  welcome_entry.go
  theme_entry.go
  reply_entry.go
  reply_image.go

admin_entry.go は管理者コマンド、welcome_entry.go は新規加入者への反応、theme_entry.go はお題、reply_entry.go は通常返信の入口。

scheduler側

internal/scheduler/
  scheduler_entry.go

scheduler側では、放置投稿と定時画像投稿の入口を分けた。ここで FEATURES を見て、該当機能がOFFなら動かないようにしている。

なぜ分けたのか

コミュニティBOTは、機能が増えるとすぐに「どこで何が動いているか」が分からなくなる。GPTとの対話では、まず機能名を決め、次に入口ファイルを作り、最後に既存処理をそこへつなぐという順番で進めた。

この段階で、base-botは「全部入りのPlugin」から「必要な機能を選べるPlugin」に近づいた。
