第15〜21段階 / 機能入口の分離

handlerとschedulerを分解する

機能が増えるほど、どこで何が動いているか分からなくなる。そこでhandlerとschedulerの入口を分けた。

internal/ ├─ handler/ │ ├─ admin_entry.go 管理者コマンド入口 │ ├─ welcome_entry.go 新規加入者向け入口 │ ├─ theme_entry.go お題投稿入口 │ ├─ reply_entry.go 自動返信入口 │ └─ reply_image.go 画像返信判定 └─ scheduler/ └─ scheduler_entry.go 定時投稿・放置投稿入口

ここで重要なのは、機能そのものを全部書き直したわけではないこと。まず「入口」を作り、そこに config.HasFeature() を置いた。

投稿イベントHandleへ入る
入口関数FEATURESを見る
有効なら処理返信・歓迎・お題
無効なら通過余計な動作をしない
作業者機能を全部バラバラにした方がいい？
GPT最初から大改造せず、入口を薄く分けるのが安全です。既存処理は残して、ON/OFF判定だけ前段に置きましょう。

この段階で得たこと

base-botは「全部入りPlugin」から「必要な機能を選べるPlugin」になった。配布する時にも、コミュニティごとに使う機能を選びやすくなる。
