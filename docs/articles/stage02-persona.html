第09〜14段階 / 人格と機能切替

人格を「コード」から切り離す

次にやったのは、BOTのキャラクター性をGoコードから切り離して、personas フォルダに逃がすことだった。

この作業で、虚無猫、フジタ、base人格のように、複数の人格を切り替えられるようになった。

人格フォルダ

personas/
  base/
    persona.json
  fujita/
    persona.json
  kyomu_neko/
    persona.json
  suita_coffee/
    persona.json

各人格は persona.json を持つ。ここに名前、説明、反応ワード、口調、システムプロンプト、禁止事項などを書く。

環境変数で人格を指定する

PERSONA=kyomu_neko
PERSONA_PATH=personas/kyomu_neko/persona.json
IMAGE_REF_DIR=assets/kyomu_neko/refs
FEATURES=reply,theme,scheduled_image,idle_post,image_reply,welcome,admin

PERSONA は現在の人格名。PERSONA_PATH は実際に読むJSON。FEATURES はどの機能を使うかの一覧。

機能切替の考え方

全部入りのBOTは便利そうに見えるけれど、実際にはコミュニティごとに必要な機能が違う。歓迎だけ使いたい場合もあれば、定時投稿だけ使いたい場合もある。そこで FEATURES で機能を切れるようにした。

GPTとの対話では、「人格切替」と「機能切替」を別物として扱うことをかなり意識した。人格はキャラ、機能はPluginの振る舞い。この分離が後のconfiguiにつながった。

この段階の成果

  • 虚無猫人格を追加
  • base / fujita / kyomu_neko の切替を確認
  • switch系PowerShellを追加
  • 文字化け対策としてUTF-8 BOMなし保存を意識
