共有方針

公開ノートに載せるのは、構造、判断、公開可能な手順、モックです。APIキー、Client Secret、Railway Variablesの実値、.env、logs、実コミュニティの投稿データは載せません。

公開しないもの

  • OPENAI_API_KEY
  • mixi2 Client Secret
  • Railway Variablesの実値
  • .env本体
  • logs
  • ユーザー情報や投稿本文

共有時の実務ルール

共有用の記事やスクリーンショットを作る時は、まず「これは公開してよい情報か」を確認します。フォルダ構成、機能名、設定項目名、確認コマンド、失敗例、Requirementの注意は共有できます。一方で、APIキー、Client Secret、Railway Variablesの実値、.env、logs、実コミュニティの投稿本文、ユーザー情報は共有しません。

特に注意すべきなのは、設定例を貼る時です。キー名だけを示すつもりでも、実値が残ったまま貼ってしまう可能性があります。公開資料では <Railwayで実値を設定> のような表記にし、実値はRailway画面で直接入力する運用にします。

GitHub Pagesに載せる記事は、制作過程を説明するためのものであり、配布用の完成済みBOTではありません。受け取った人が自分のmixi2 Pluginアプリ、自分のOpenAI APIキー、自分のRailway環境、自分のGitHub repo、自分の人格データを用意する前提です。

この共有方針を守ることで、制作ノウハウは残しつつ、秘密情報や実運用データを外へ出さない状態を維持できます。

公開ノートとしての完成条件

公開ノートとして完成している状態とは、単にHTMLが表示されることではありません。読んだ人が、どのフォルダを触り、どの設定を確認し、どのサービスで何を用意し、どの情報を公開してはいけないか理解できる状態です。そのため、制作ノートでは、見た目の装飾よりも、作業の再現性と安全性を優先します。

ページを更新する時は、TOPから各ページへ移動できること、詳細記事に前後ボタンがあること、各ページ下部にTOPへ戻るリンクがあること、スマホで横にはみ出さないこと、Secretや実ログが含まれていないことを確認します。これらは公開前の最低限のレビュー項目です。

共有範囲の判断に迷った場合は、「その情報を見た第三者が外部サービスへアクセスできるか」「実コミュニティの内部情報が分かるか」「特定ユーザーの行動や投稿が分かるか」を基準にします。該当する場合は公開しません。

共有前の最終レビュー

公開前には、ページ本文だけでなく、画像、HTMLソース、CSS、JSON、ZIP内のファイル名も確認します。本文にSecretを書いていなくても、スクリーンショットにRailway Variablesが写っていたり、ZIPの中に古い.envやlogsが混ざっていたりすると公開事故になります。

このため、公開ノートを作る時は、docs配下だけを対象にし、Plugin本体repoや作業中の一時フォルダを混ぜないようにします。Gitへ追加する時も git add . ではなく、git add .\docs のように範囲を限定します。バックアップフォルダや展開用一時フォルダはcommit対象に入れません。
