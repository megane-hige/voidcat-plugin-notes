Config UIとは

cmd/configui は、人格設定をブラウザで編集するためのローカル専用UIです。PowerShellで日本語JSONを直接触ると文字化けしやすいため、フォームから編集できるようにしています。

主要コンフィグ

キー意味注意
PERSONA使用する人格キー。専用repoの人格名と揃える。
PERSONA_PATH人格シートのパス。Test-Pathで確認。
IMAGE_REF_DIR画像参照素材の場所。画像機能使用時に必要。
MIXI2_CLIENT_IDmixi2 PluginのClient ID。公開記事に実値を載せない。
MIXI2_CLIENT_SECRETmixi2 PluginのClient Secret。Railwayで実値。空欄上書き禁止。
OPENAI_API_KEYOpenAI APIキー。公開禁止。
FEATURES有効機能一覧。不要機能は外す。
EVENT_LOG_PATHイベントログ保存先。/data配下推奨。
REPLIED_LOG_PATH返信済みID保存先。重複返信防止。

空欄上書き注意

MIXI2_CLIENT_SECRET="" や OPENAI_API_KEY="" をRailwayへ貼ると実値が消えます。SecretはRailway画面で直接入力し、記事やテンプレには実値を書きません。

ローカル.envとRailway Variablesの違い

ローカルでは .env を使って確認できますが、本番RailwayではVariablesが本体です。Config UIのローカル.env補助設定は、開発中に値を整えるためのものであり、Railway本番のSecretを直接更新するものではありません。ここを混同すると、ローカルでは動くのに本番で動かない、または本番のSecretを空欄で上書きする事故につながります。

Railway Variablesへ貼るときは、実値を含むSecret系と、公開可能な通常設定を分けて扱います。記事やテンプレートにはSecretの実値を書かず、キー名と役割だけを載せるのが安全です。

設定確認の順番

  1. PERSONA、PERSONA_PATH、IMAGE_REF_DIR が専用repoに合っているか見る。
  2. FEATURES が必要な機能だけを含んでいるか見る。
  3. OpenAIとmixi2のSecretが空欄ではないかRailway画面で見る。
  4. ログや状態ファイルの保存先が /data 配下になっているか見る。
  5. Railway serviceに /data Volumeが付いているか見る。

運用時の設定レビュー

本番運用では、設定は一度入れて終わりではありません。投稿頻度が高すぎる、画像生成が重い、返信が多すぎる、静寂投稿が場に合わない、といった問題は運用後に見えてきます。そのため、Config UIとRailway Variablesを見ながら、必要な項目だけを調整します。

調整する時は、まずFEATURESで大きく止めるか、個別の確率や時刻で細かく調整するかを決めます。たとえば画像返信だけが多いなら REPLY_IMAGE_PROBABILITY_PERCENT を下げます。画像生成全体を止めたいなら OPENAI_IMAGE_ENABLED=false を使います。

設定変更後は、Railwayの再デプロイまたは再起動が必要な場合があります。変更が反映されているかはログで確認します。
