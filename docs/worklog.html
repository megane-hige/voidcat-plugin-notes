作業記録の位置づけ

このページは、旧詳細記事の内容を現在の構成に合わせて再構成した作業記録です。単なる成功ログではなく、何を疑い、どこを分け、何を残し、何を捨てたかを追えるようにまとめています。

動いているPluginをコピーして安全地帯を作る

既に動いていたシベリア・フジタPluginを土台にしました。ゼロから作り直すのではなく、mixi2 API、OpenAI API、投稿、返信、スケジューラが動いている構成を丸ごとコピーし、安全に改造できる作業場を作る方針です。最初に go build ./... を通し、コピー直後に壊れていないことを確認しました。

この段階では設計の美しさより、壊さないことを優先しました。動く土台を持ったまま、人格や素材を外へ出し、機能の入口を整理していく順番にしました。

人格と素材を分離する

BOTのキャラクター性をコードから切り離し、人格を personas、画像素材を assets に分けました。これにより、コード本体を変えずにキャラクターだけを切り替えられるようになりました。

personas/fujita/persona.json
personas/kyomu_neko/persona.json
personas/nanchatte_ai/persona.json

assets/fujita
assets/kyomu_neko
assets/nanchatte_ai

PERSONAとFEATURESで切り替え可能にする

PERSONA、PERSONA_PATH、IMAGE_REF_DIR を環境変数化し、FEATURES で機能ON/OFFを切り替えられるようにしました。これにより、同じエンジンでも、返信だけ、画像なし、全部入りなどの運用が可能になりました。

handlerとschedulerの入口を分ける

管理者コマンド、歓迎、お題生成、自動返信、画像返信、定時投稿、静寂投稿の入口を分離しました。問題が起きたときに、返信系なのか、スケジューラ系なのか、管理者機能なのかを切り分けやすくするためです。

検証コマンドを増やす

configcheck、gptcheck、mixi2check、timelinecheck、postpreview、postcheck、streamcheck で段階確認できるようにしました。Railwayに上げる前にローカルで切り分けるためです。

OpenAI APIとmixi2 Pluginにつなぐ

OpenAI APIキー、mixi2 Client ID、Client Secret、Community IDを設定し、ローカルからAPI接続、timeline取得、投稿確認を行いました。mixi2はBotアプリではなくコミュニティ用Pluginとして扱う点が重要でした。

Railway常時稼働へ移す

RailwayではGitHub repoを接続し、Variablesを設定し、Volumeを /data にマウントしました。状態ファイルや履歴は /data へ置くことで、再デプロイ後も返信済みIDや投稿履歴を維持します。

Config UIを作る

persona.jsonを手編集し続けると、JSON構造の崩れや文字化けが起きやすいため、cmd/configui を作りました。人格選択、人格シート、機能ON/OFF、ローカル.env補助、Railway Variables確認を扱います。

3体を専用repo化する

虚無猫、フジタ、空想アイを専用repo・専用persona・専用assetsに揃えました。特に虚無猫は base-bot から mixi2-community-voidcat-plugin へ整理し、不要な他人格と他素材を削除しました。

GitHub Pagesで公開ノートを整える

Plugin本体はPrivate repoで維持し、公開可能な作業記録だけを voidcat-plugin-notes で公開します。秘密値、実ログ、投稿本文、ユーザー情報は載せません。
