作業記録の位置づけ

このページは、旧詳細記事の内容を減らさず、現在の標準構成へ合わせて再構成した作業記録です。単に何をしたかだけではなく、なぜその順番にしたのか、何を確認したのか、どこで事故りやすいのかを制作マニュアル寄りにまとめています。

全体タイムライン

第01回：動いているPluginをbase-botへ分岐する

既存Pluginを直接壊さないため、まずコピーを作る。コピー後は機能追加より先に go build ./... を通し、土台が壊れていないことを確認する。ここでの目的は、新しい設計を始めることではなく、壊れても戻れる作業場を作ること。

第02回：人格を外部ファイル化して切り替える

人格をコードから外し、personas/{persona}/persona.json に置く。画像素材は assets/{persona} に分離する。PERSONA、PERSONA_PATH、IMAGE_REF_DIR を揃えることで、同じPlugin本体を別キャラクターとして運用できる。

第03回：handlerとschedulerを機能入口で整理する

reply、theme、welcome、admin、schedulerを入口ごとに分ける。FEATURESで入口を止められるようにし、本番中でも画像機能だけ止める、返信だけ試す、管理者機能だけ残す、といった切り替えを可能にする。

第04回：検証コマンドとPowerShell作業導線を作る

configcheck、gptcheck、mixi2check、timelinecheck、postcheckを使い、設定、OpenAI、mixi2認証、投稿読み取り、投稿可否を段階的に確認できるようにする。PowerShellではUTF-8 BOMなし、検索対象除外、.ps1実行ポリシーに注意する。

第05回：OpenAI APIとmixi2 Pluginにつなぐ

OpenAI APIキー、mixi2 Client ID、Client Secret、Community IDを設定し、API接続を確認する。mixi2はBotアプリではなくコミュニティ用Pluginとして扱い、Requirement、Application Version、再許可を忘れない。

第06回：GitHubとRailwayで本番稼働させる

Plugin本体はGitHub Private repoへ置き、Railwayで常時稼働させる。.envやlogsはGitHubへ入れず、SecretsはRailway Variablesで設定する。状態ファイルは /data Volumeへ置く。

第07回：虚無猫の人格調整とconfiguiの追加

persona.jsonを手編集し続けると壊れやすいため、Config UIを追加する。人格選択、人格シート、機能ON/OFF、ローカル.env補助設定、Railway確認欄を整理する。

第08回：作業ログを公開サイトとして作り直す

Plugin本体とは別にGitHub Pages用repoを持ち、公開可能な制作記録だけを載せる。秘密値、実ログ、投稿本文、ユーザー情報は載せない。

今回：三体標準化

虚無猫だけbase-bot名義だった状態を解消し、Voidcat、Fujita、Nan AIを専用repo構成へ揃える。base-botは共通テンプレとして復元する。

失敗・詰まりポイント

問題原因対策
虚無猫がbase-botなのか本番repoなのか分からないローカルフォルダ名とGitHub remoteの役割がズレていた。Voidcat専用repoへリネームし、base-botはテンプレへ戻す。
batが文字化けする日本語入りbatの文字コードが崩れた。ASCII版batへ変更する。
docsを丸ごと消して旧記事が消えたように見えるZIPの中身を置換する方針だった。詳細記事を再生成し、前後ナビとモックを戻す。
RailwayでSecretが消える空欄テンプレをVariablesへ貼った。SecretはRailway画面で実値入力し、空欄上書きしない。
VolumeがないRailway serviceに/data Volumeが付いていない。各serviceでVolume表示とMount Pathを確認する。
