今回の更新概要

今回の作業では、虚無猫、シベリア・フジタ、空想アイの3体Pluginを同じ考え方で管理できるようにしました。以前は虚無猫だけが base-bot 名義のフォルダに残っており、実体としてはVoidcat用GitHub repoを向いているのに、ローカル上では共通テンプレなのか本番repoなのか分かりにくい状態でした。

この混線を解消するため、虚無猫を mixi2-community-voidcat-plugin として専用repo化し、フジタ、空想アイと同じ構成へ揃えました。base-bot はRailway本番には使わず、今後のコピー元・共通テンプレとして扱います。

今回実施した作業

分類内容確認
三体標準化Voidcat、Fujita、Nan AIを専用repo・専用persona・専用assetsへ統一。各repoで不要人格と不要素材を整理。
base-bot再定義base-botを共通テンプレとして復元。Railway本番には使わない。
Config UI人格選択、人格シート、機能ON/OFF、ローカル.env補助設定、Railway確認欄を整理。本番Railwayを直接変更するUIではない。
起動導線open-configui.batとショートカットを作成。ASCII版にして文字化け回避。
Railway確認VoidcatのSecrets空欄、FujitaのVolume未表示を確認。Railway画面で実値とVolumeを確認する。
docs再構成ページ構成を制作マニュアル寄りに再編。固定表示はタイトルだけ、詳細記事と前後ボタンを復活。

作業後の判断基準

今回の更新で重要なのは、見た目の整理ではなく、運用単位を明確にしたことです。フォルダ名、GitHub repo名、Railway service名、persona名、assets名が揃っていると、障害時に「どこを見ればよいか」が大きく変わります。逆に、ここがズレていると、正しいrepoへcommitしてもRailwayが別repoを見ていたり、別人格の素材を参照したりします。

そのため、今回の完了判定は「ページができた」ではなく、「3体それぞれの運用単位が明確になり、Config UIの入口も揃い、Railwayで確認すべき残項目が分離された」ことです。SecretsやVolumeのようにRailway画面でしか直せないものは、コード修正とは別タスクとして残します。
